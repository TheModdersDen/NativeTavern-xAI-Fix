# NativeTavern 本地优先开发计划

更新日期：2026-08-07

## 1. 产品边界

NativeTavern 是本地 App，不运营中转 API、语音、图片、向量或 MCP 云服务。

1. 能复用当前 LLM 配置的功能直接复用，不要求重复填写 API Key。
2. 能在本地完成的能力优先使用 SQLite、FTS、规则引擎和系统 API。
3. 系统 TTS/STT 只要求操作系统权限与设备能力；系统实现是否联网必须向用户说明。
4. 云端或自托管 TTS/STT、图片、Embedding、MCP 均为可选 BYOK。
5. 本地模型包必须明确下载大小、磁盘占用、内存需求和预计性能。
6. 每项能力在 UI 中统一标记为：内置、复用当前 AI、需要权限、需要下载、外部服务。

## 2. Phase 0：Live2D 视觉基础

当前 MVP 已完成：

- 解析每个 `model3.json`，不写死动作分组或索引。
- 三个测试模型可按角色分配，自动识别空闲、点击、说话和响应动作。
- 配置保存到角色 `assetsJson`，不污染 SillyTavern 角色卡扩展字段。
- 视觉小说模式可在没有图片背景时由 Live2D 独立启用。
- 加载失败或平台不支持时回退到现有表情立绘。
- 预留 `ParamMouthOpenY` 控制接口，供后续 TTS 嘴型同步。
- 支持从本地 ZIP 导入用户模型，包含路径穿越、符号链接、大小和资源引用校验。

发布前剩余工作（P0）：

- 在 Android 真机与 iOS 真机验证透明度、裁切、触摸、前后台暂停和长时间功耗。
- 支持删除已导入的用户模型，并处理正在被角色引用时的确认与回退。
- 为动作增加可选的语义映射：空闲、点击头部、点击身体、说话、完成、情绪。
- 精确锁定并 fork/vendor Flutter 桥接层，审计 Cubism SDK/Core 版本与二进制来源。
- 确认三个测试模型的再分发许可；不满足时只保留开发样本，不进入发行包。
- 完成 Live2D、模型作者与 Release License 的发布清单。

验收：连续切换 20 次角色无崩溃；后台渲染停止；损坏模型可恢复；未配置 Live2D 的聊天行为零变化。

## 3. Phase 1：记忆系统（最高优先级）

目标：解决长对话遗忘、上下文费用高、用户无法检查 AI 记住了什么。

- SQLite FTS5/BM25 本地检索，第一版不依赖 Embedding。
- 复用当前 LLM，从对话提取人物、关系、事件、承诺和偏好候选。
- 记忆收件箱：用户可确认、修改、锁定、合并、遗忘。
- 短期摘要、情节摘要、长期事实分层，记录来源消息和更新时间。
- 注入预算、冲突检测、过期策略和“本次实际使用了哪些记忆”的可视化。
- Embedding 作为后续可选增强：复用已配置提供商或下载本地模型。

配置：默认零新增配置；自动提取复用当前 LLM。没有 LLM 时仍可手动维护和全文检索。

验收：1000 条消息可稳定检索；每条注入记忆可追溯；关闭功能后提示词与现状一致。

## 4. Phase 2：本地场景/RPG 引擎

目标：增加真正可玩的状态、失败条件和重复游玩价值，而不是只靠提示词假装有规则。

- 确定性本地状态：属性、变量、背包、关系、时间、地点、任务和冷却。
- 骰点、技能检定、资源消耗、条件分支由本地引擎执行，LLM 只负责叙事。
- 状态面板、行动菜单、回合日志、存档快照、回滚和分支时间线。
- JSON/YAML 行为包，提供可视化编辑器和版本声明。
- 角色卡、世界书、变量系统和快捷回复之间建立明确的数据契约。

配置：选择场景包即可；叙事复用当前 LLM；规则执行无需 API。

验收：相同随机种子与输入得到相同状态；LLM 输出不能绕过规则修改受保护状态。

## 5. Phase 3：角色工坊与角色卡体检

目标：降低角色创建门槛，修复角色卡质量不稳定和提示词冲突。

- 分步角色创建：身份、动机、边界、说话风格、关系和开场场景。
- 本地规则体检：缺字段、重复描述、宏错误、格式问题、世界书冲突和过长字段。
- 提示词预览：展示最终注入顺序、来源、Token 占用和被截断内容。
- 可选 AI 改写、补全与多开场生成，全部复用当前 LLM。
- 导入后生成兼容性报告，原始角色卡始终可恢复。

配置：本地体检零配置；AI 辅助复用当前 LLM，不新增服务设置。

## 6. Phase 4：语音与 Live2D 沉浸

目标：先提供设备可用的基本体验，再允许高级用户接入外部语音。

- 系统 TTS：按角色选择系统声音、语速和语言，支持队列、停止和锁屏中断。
- 系统 STT：按住说话、实时文本、编辑后发送、权限和离线能力提示。
- Live2D 嘴型：从本地播放音频的振幅包络驱动 `ParamMouthOpenY`，不依赖云服务。
- 动作编排：消息开始、句子边界、情绪、点击和空闲超时触发动作。
- 外部适配器作为可选项：ElevenLabs、OpenAI-compatible、自托管 TTS/STT。

配置：系统语音只需权限和一次声音选择；外部语音必须由用户提供地址、Key 或本地服务。

验收：未配置外部服务时系统语音完整可用；停止播放立即归零嘴型；权限拒绝不会阻塞文字聊天。

## 7. Phase 5：本地资料库（Data Bank）

目标：让角色可靠使用长文档，同时保持数据可检查、可删除、可迁移。

- 本地导入 TXT、Markdown、HTML、PDF、EPUB；保留文档、章节和页码来源。
- 本地切块、FTS 检索、引用预览、文档启停和按聊天/角色绑定。
- 当前 LLM 可用于摘要、关键词和查询改写，但导入与检索不依赖 LLM。
- Embedding 和重排器为可选增强，支持 BYOK 或明确下载的本地模型。

配置：基础全文检索零服务配置；用户只选择文件。语义检索按需配置或下载。

## 8. Phase 6：工具调用与 MCP

目标：解决“只能聊天、不能行动”，同时控制本地 App 最重要的权限风险。

- 支持 OpenAI-compatible tool calling，并提供无原生工具调用模型的结构化降级路径。
- MCP 连接管理、能力发现、逐工具授权、参数预览、确认和执行日志。
- 文件、网络、剪贴板等高风险能力默认拒绝；角色卡不能自行提升权限。
- 只读/写入/外部副作用分级；写入操作支持 dry-run 或二次确认。
- 本地行为包可以组合变量、快捷回复、工具和 UI 面板。

配置：高级功能，必须显式添加 MCP 服务器或本地命令；默认聊天零配置、零权限扩张。

## 9. Phase 7：可选本地模型包

目标：在用户主动选择时实现完全离线，而不是把大模型下载伪装成零配置。

- 先做能力检测与运行器适配，不自研推理引擎。
- 模型目录展示量化、大小、上下文、内存估算、许可证和设备适配结果。
- 下载可暂停、校验、迁移和彻底删除；低内存设备有明确保护。
- LLM、Embedding、STT、TTS 模型分别管理，不捆绑下载。

配置：必须由用户选择下载；永远保留现有 BYOK 与局域网服务路径。

## 10. 建议排期与依赖

以 1 个 Sprint = 2 周估算：

| 里程碑 | Sprint | 主要交付 |
| --- | ---: | --- |
| M0 Live2D 稳定化 | 1–2 | 双端验证、ZIP 导入、运行时 fork、许可门槛 |
| M1 记忆系统 | 2–3 | FTS、记忆收件箱、注入与追溯 |
| M2 RPG 引擎 | 3 | 状态机、检定、行为包、存档回滚 |
| M3 角色工坊 | 1–2 | 向导、体检、提示词预览 |
| M4 语音沉浸 | 2 | 系统 TTS/STT、嘴型、动作编排、BYOK 适配器 |
| M5 资料库 | 2–3 | 文档管线、FTS、引用、可选语义检索 |
| M6 MCP | 2–3 | 权限模型、确认、日志、工具适配 |
| M7 本地模型 | 独立评估 | 设备检测、模型管理、运行器适配 |

优先顺序不建议调整为“先接更多云 API”。记忆、规则状态、角色体检和资料检索能复用现有 LLM 或完全本地实现，覆盖面更大，也更符合 NativeTavern 的产品边界。

## 11. 工程横切要求

- 为所有可选能力建立统一 Capability Registry 和设置状态诊断。
- 数据库变更必须迁移、备份、回滚，并有真实持久化回归测试。
- 所有 LLM 派生数据保存来源、模型和时间，允许用户删除与重新生成。
- 外部调用显示目标域名、数据范围、预计费用归属，并写入本地审计日志。
- 大文件、模型和媒体统一配额、清理与孤儿文件扫描。
- Android/iOS 真机测试覆盖低内存、后台恢复、权限拒绝、离线和弱网。
